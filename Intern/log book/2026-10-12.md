## 2. Sinkronisasi Petugas Baru (bug fix)
- Bug 1 (backend): `/officers/my-region` bisa MENGECUALIKAN petugas peminta sendiri bila junction `officer_regions` belum lengkap → petugas hilang dari daftar "Ganti Petugas" di perangkatnya sendiri.
  - Fix: self-include dijamin — bila `meId` tidak ada di hasil, petugas peminta ditambahkan dengan fallback regions dari kolom lama.
- Bug 2 (mobile): `persistRoster()` menyimpan hash PIN server dengan `void setPinHash(...)` (fire-and-forget). Bila app ditutup sebelum async writes selesai, hash petugas baru hilang → petugas baru admin-created tidak bisa login offline.
  - Fix: loop penyimpanan hash PIN sekarang `await` (per petugas, dibungkus try/catch per baris agar satu gagal tidak membunuh sisanya).

## Kesalahan saya hari ini & cara mengatasinya

### Kesalahan 1: Sintaks TypeScript di file JavaScript backend
- Saya menulis `const requestedOfficerIds = new Set<string>();` di `officers.js` — file Node.js biasa (CommonJS), bukan TypeScript. Langsung `SyntaxError: Unexpected token ')'` saat `node --check`.
- Pelajaran: backend ini JavaScript murni; tipe generik `Set<string>` hanya valid di `.ts`. Kalau backend kembaran TypeScript/JS, selalu cek ekstensi file sebelum menulis.
- Fix: hapus `<string>` → `new Set()`, verifikasi ulang dengan `node --check` semua file yang diedit.

### Kesalahan 2: Alur sync geofence belum tersambung (glue code terlewat)

- Fix: panggil di `adminPull.syncOnResume()` + refactor `location.ts` agar membaca config hasil sync, bukan konstanta startup.
