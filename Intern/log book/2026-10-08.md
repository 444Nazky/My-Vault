## Bug: Edit Trip yang Sudah Terkirim

**Gejala:** setelah foto atau info trip (mis. plat nomor) diubah, status trip berubah
jadi "menunggu koneksi / tersimpan di lokal" dan perubahan tidak sampai ke dashboard.

**Akar masalah (dua lapis):**

1. **Backend** — `POST /trips/complete` hanya bisa INSERT. Resend trip yang diedit
   bukan memperbarui, tapi (setelah guard anti-duplikat) dibuang sebagai duplikat →
   edit hilang; sebelum guard → trip ganda.
2. **Mobile** — `mergeTrips()` memprioritaskan `synced:true` di atas `synced:false`,
   sehingga hasil edit bisa ditimpa salinan lama saat rekonsiliasi localStorage↔IndexedDB.

**Perbaikan:**

- Backend `routes/trips.js`: kolom `trips.client_trip_id` (migrasi idempotent di
  `db.js`) + **upsert** — bila `client_trip_id` sudah ada, `UPDATE trips` dan ganti
  seluruh kendaraan/foto, balas **200 `{updated:true}`**; hanya trip baru yang INSERT.
- Mobile `pages/store.tsx`: tambah `Trip.updatedAt`; `patchTripPhoto()` &
  `patchVehiclePhoto()` menstempel waktu. `mergeTrips()` memilih `updatedAt` terbaru
  lebih dulu; aturan `synced` hanya tie-breaker data lama.
- Mobile `HistoryDetailScreen.tsx`: tambah editor inline per kendaraan
  (**Ubah** → plat/jenis/golongan → **Simpan & Kirim**) yang memicu resend upsert.

## Bug Susulan: Akun Terkunci "Belum Memiliki Akses Dermaga"

**Gejala (setelah update OTA):** Beranda menampilkan "Akun ini belum memiliki akses
dermaga — trip belum bisa dimulai" + tombol "Hubungi Admin"; `Mulai Trip` nonaktif.

**Akar masalah (data mapping saat sinkron):** `syncOfficersToLocal()` menggabungkan
roster dengan cara server-menang. `toMobileOfficer()` menyetel
`dermagaAccess: bo.dermagas || []`. Bila `/officers/my-region` membalas `dermagas: []`
(link belum tersinkron / DB lama), nilai kosong itu **menimpa** scope dermaga lokal/seed
yang tadinya valid → `officer.dermagaAccess` jadi `[]` → HomeScreen (`hasDockAccess`)
salah mengunci.

**Perbaikan (satu titik, jangan biarkan sync mengosongkan scope):**
- `services/officers.ts`: saat upsert, server officer dengan `dermagaAccess` kosong
  mengambil alih dari entri lokal/seed yang punya akses.
- `pages/store.tsx`: helper baru `healDermagaAccess()` — roster dari cache lama
  (yang sudah terlanjur kosong) diisi ulang dari seed saat aplikasi dibuka.
- `store.tsx` (rapian): `SettingsScreen` `pendingCount` tak terpakai → `[, setPendingCount]`.

**Test:** `store.merge.test.ts` +3 (healDermagaAccess) → **38 test lulus**; `tsc` 0 error.

> Ceiling (ponytail): petugas **buatan server** yang tidak ada di seed tetap bisa
> terkunci bila server sungguh mengirim dermagas kosong — itu kasus data admin,
> bukan kode; upgrade path = pastikan `officer_dermagas` terisi dari tab akses dermaga.

## Ponytail Audit (over-engineering) + Diagnosis OTA + Audit Commit

### Metode
`ponytail-audit` (mode full) — scan tree penuh, bukan diff. Pengecualian:
correctness bug → perbaiki terpisah.

### Diagnosis: "updates masih sering gagal tertarik"
**Akar masalah:** `scripts/publish-ota-git.mjs` & `publish-ota-version.js` pernah
dijalankan **tanpa `www/` ter-build** → `version.json` terpublish dengan
`assets: []` (dan `ota/index.html` 404). Perangkat melihat versi baru, lalu
`checkForUpdate` gagal di guard `if (!remote.assets.length)` (ota.ts:408) secara
**senyap** → "tidak tertarik". Kedua: unduh aset (~20 file) **tanpa retry** — 1
kejut transient (429/throttle GitHub raw) membuang seluruh bundel.

**Perbaikan:**
- `ota.ts`: `downloadAsset` retry 3× backoff pendek (600/1200/1800 ms), retry pada 429/5xx.
- `publish-ota-git.mjs` & `publish-ota-version.js`: **guard kosong** — tolak publish
  bila `www/` tak memuat `index.html` (`exit 1`). Agar manifest kosong tidak pernah naik.

**Status produksi:** `version.json` live masih `assets: []` (404) — **harus di-publish
ulang**: `npm run build && npm run ota:publish`. Belum diberi tahu ke GitHub.
